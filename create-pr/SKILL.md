# Создание PR
Следуй этим инструкциям при оформлении PR.

## Оформление

- Заголовок — на английском, Conventional Commit:
  `type(scope): summary`. При squash станет коммитом в `master`.
- Описание — на русском.
- Связь с задачей если есть — `Closes #N`.
- Создавай PR как draft.

## Тело
Заполни эти разделы.

### Решения и отклонения

Основание для записи: реализация отличается от договорённостей в issue
или потребовала существенного решения по вопросу, который issue
не определяло.

Формат: что предполагалось или выяснилось → что решили → почему →
последствия и компромиссы. Для отклонений укажи, согласованы ли они.
Если таких решений нет — напиши «Нет».

### На что обратить внимание

Основание для записи: есть конкретная причина сомневаться
в корректности изменения, а возможная ошибка имеет существенные
последствия.

Формат: где смотреть → какой сценарий может сломаться → последствия →
почему именно это изменение вызывает сомнение.
Если таких мест нет — напиши «Нет».

### Нерешённые вопросы и ограничения

Если есть — укажи, что осталось нерешённым и как влияет на результат.
Иначе удали раздел.

### Before merging

Если есть — перечисли необходимые действия до мержа, отличающиеся от стандартного флоу.
Иначе удали раздел.
