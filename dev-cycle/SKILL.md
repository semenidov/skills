# Dev Cycle

Старт: PREPARE.
Завершение: HANDOFF.

## Общие правила

- Работа ведётся в одной ветке и одном PR.
- Мейн — основная оркестрирующая сессия; implementer реализует слайс, отдельный reviewer проверяет итоговый diff.
- Мейн дублирует отчёты и результаты их оценки комментариями в PR.
- После запуска субагента мейн дожидается отчёта и самостоятельно выполняет следующий переход. Не завершать работу между этапами в ожидании сообщения владельца.
- При блокере, который нельзя устранить в рамках задачи и доступов, сообщить владельцу текущую ноду, причину и необходимое действие; не повторять безрезультатные попытки бесконечно. По просьбе владельца остановиться.
- Для PREPARE, создания PR и независимого ревью использовать соседние скиллы prepare-dev, create-pr и code-reviewer соответственно.

## PREPARE — Проверить окружение

Кто: мейн.
Вход: окружение.
Действие: проверить среду по prepare-dev. Устранить блокеры до разработки.
Результат: окружение готово к работе.

Переходы:
- Окружение готово → CREATE_BRANCH.
- Остались блокеры → PREPARE.

## CREATE_BRANCH — Создать ветку

Кто: мейн.
Вход: готовое окружение.
Действие: сохранить посторонние изменения, не теряя их; обновить базовую ветку проекта (master/main) и создать ветку для issue. При продолжении работы использовать существующую ветку и PR.
Результат: рабочая ветка для реализации.

Переходы:
- Ветка создана → IMPLEMENT с первым слайсом.

## IMPLEMENT — Выполнить слайс

Кто: субагент implementer.
Вход: текущий слайс; при доработке — замечания основной сессии.
Действие: реализовать решение, запустить написанные тесты, проверить критерии, запушить изменения и вернуть отчёт. После первого push создать draft PR по create-pr, если его ещё нет. Следующие слайсы публиковать в тот же PR.
Результат: реализация слайса и отчёт о выполнении.

Переходы:
- Отчёт получен → CHECK_REPORT.

## CHECK_REPORT — Проверить отчёт

Кто: мейн.
Вход: отчёт разработки по текущему слайсу.
Действие: разобрать проблемы, оценить их критичность * вероятность. Объяснить отклонённые замечания. Подготовить комментарии к необходимым исправлениям.
Результат: решение о принятии результата или доработке.

Переходы:
- Требуются исправления → IMPLEMENT с замечаниями.
- Результат принят → CHECK_CI.

## CHECK_CI — Проверить CI и устранить сбои

Кто: мейн.
Вход: принятый результат текущего слайса и доступ к CI из PR.
Действие: проверить CI последнего коммита PR.
При красном CI — исправить сбои, проверить затронутую
область локально и запушить.
Результат: CI последнего коммита зелёный.

Переходы:
- CI зелёный → NEXT_SLICE.
- CI выполняется → дождаться через wait-ci.sh проекта, если он есть, иначе через доступное средство ожидания CI → CHECK_CI.

## NEXT_SLICE — Выбрать следующий шаг

Кто: мейн.
Вход: завершённый слайс и список оставшихся слайсов.
Действие: определить, остались ли слайсы для реализации.
Результат: выбран следующий слайс или итоговое ревью.

Переходы:
- Остались слайсы → IMPLEMENT со следующим слайсом и новым субагентом.
- Все слайсы завершены → FINAL_REVIEW.

## FINAL_REVIEW — Провести независимое ревью

Кто: отдельный субагент reviewer без истории реализации.
Вход: итоговый diff всей фичи.
Действие: провести независимое ревью по скиллу code-reviewer.
Результат: отчёт code-reviewer.

Переходы:
- Отчёт получен → FIX_REVIEW.

## FIX_REVIEW — Оценить и исправить замечания ревью

Кто: мейн.
Вход: отчёт код ревью.
Действие: оценить критичность и вероятность каждого замечания.
Выбрать необходимые к исправлению.
Объяснить отклонённые замечания.
Исправить подтверждённые проблемы, запустить затронутые тесты.
Результат: отчёт по отклонённым замечаниям и выполненным исправлениям.

Переходы:
- Отчёт получен → FINAL_CI.

## FINAL_CI — Проверить CI и устранить сбои

Кто: мейн.
Вход: отчёт по ревью и доступ к CI из PR.
Действие: проверить CI последнего коммита PR.
При красном CI — исправить сбои, проверить затронутую
область локально и запушить.
Результат: CI последнего коммита зелёный.

Переходы:
- CI зелёный → HANDOFF.
- CI выполняется → дождаться через wait-ci.sh проекта, если он есть, иначе через доступное средство ожидания CI → FINAL_CI.

## HANDOFF — Передать на приёмку

Кто: мейн.
Вход: итоговая реализация после ревью с зелёным CI.
Действие: перевести PR в ready for review и передать владельцу отчёт с результатом.
Результат: работа передана владельцу на приёмку.

Переходы:
- Передача выполнена → конец процесса.
